# Telegram Chat Stats

[![License: GPL-3.0](https://img.shields.io/badge/license-GPL--3.0-blue.svg)](LICENSE)
[![PHP](https://img.shields.io/badge/PHP-%3E%3D8.4-8892BF.svg)](composer.json)

Личный PHP CLI-инструмент: парсит **HTML-экспорты чатов Telegram Desktop** и генерирует
по **одной статической HTML-странице статистики** на чат. Без фреймворка, без веб-сервера,
без базы данных и тестов — нужен только PHP и папка с экспортом.

[Read in English](README.md)

---

## Возможности

- Одна команда — одна статическая страница: работает офлайн, без трекинга и сервера.
- **27 сворачиваемых панелей статистики**:
  - общее (сообщения, знаки, участники, даты, матрица реплаев);
  - по участникам (сообщения, знаки, средняя длина, активность по дням недели/часам);
  - медиа по типам и участникам, популярные слова (с облаком слов) и уникальные слова;
  - **реакции** (топ эмодзи, по типам, лидеры по полученным реакциям, топ сообщений);
  - **правки**, **пересылки** (по участникам и источникам), **топ сайтов** из превью ссылок;
  - **медиа-вес** (объём документов, длительность голосовых/видео), **опросы**;
  - **скорость ответа** (медианное время), **хронотипы** (сова / жаворонок);
  - **тепловая карта активности** (день недели × час), **серии дней**, **последняя активность**;
  - **само-ответы**, **самые длинные сообщения**.
- **Дашборд** с KPI-карточками и **«забавными фактами»** вверху страницы.
- **Светлая/тёмная тема** (переключатель сохраняется в `localStorage`), адаптивная вёрстка.
- Экономная память: сообщения читаются потоково чанками, пик памяти не зависит от размера чата
  (чат на 1.1M сообщений — ~350 МБ на первом полном прогоне, повторные ~40 МБ за счёт кэша результатов).
- Поддерживает **два поколения разметки экспорта** Telegram Desktop (старую и новую 2025+),
  включая русские даты вида `11 декабря 2022, 22:51:24`.
- Режим `--nicks`: ники со ссылками на профиль из ручной карты (в экспорте username нет).

## Требования

- PHP >= 8.4 (с расширением `ext-mbstring`) **или** Docker (см. ниже — PHP на хосте не нужен)
- Composer (только для установки без Docker)

## Установка

```bash
git clone https://github.com/okopok/telegram-chats-stats.git
cd telegram-chats-stats
composer install
```

Как получить экспорт: Telegram Desktop → откройте чат → ⋮ → *Экспорт истории чата* →
отметьте HTML, скачайте получившуюся папку.

## Запуск через Docker (PHP на хосте не нужен)

Если есть Docker, а ставить PHP и зависимости на хост не хочется:

```bash
# Собрать образ один раз
docker build -t chatstats .

# Сгенерировать страницу (папка экспорта монтируется read-only, результат — в ./var/html)
docker run --rm \
  -v /путь/к/экспорту:/export:ro \
  -v $(pwd)/var:/app/var \
  chatstats generate /export --key=my-chat
```

- Обязательный монт — только папка экспорта (read-only в `/export`).
  Смонтируйте `./var`, чтобы HTML-результат и кэши сохранялись на хосте; без этого
  результат останется внутри контейнера (`var/html/<key>.html`).
- Все опции CLI работают как обычно: `--nicks`, `--limit`, `--no-cache` и т.д.
  (см. таблицу ниже).
- `docker run --rm chatstats list` — список команд и справка.

## Использование

```bash
php bin/chatstats generate <папка-экспорта> [опции]
```

Единственный обязательный аргумент — папка с экспортированным чатом.
Результат записывается в `var/html/<key>.html`.

### Опции

| Опция | Описание |
|---|---|
| `<папка-экспорта>` | Папка с HTML-экспортом чата (обязательна). Папки нет → ошибка, **exit 1**. |
| `--key=<ключ>` | Имя выходного файла: `var/html/<key>.html`. По умолчанию — имя папки экспорта. |
| `--title=<заголовок>` | Заголовок страницы. По умолчанию — ключ. |
| `--no-cache` | Не читать и не писать кэш сообщений. |
| `--rebuild` | Принудительно пересобрать кэш сообщений. |
| `--limit=<N>` | Обработать только первые **N** сообщений — быстрые проверки на больших чатах. Кэш отдельный (суффикс `-limit-N`), полный кэш сохраняется. Выводит предупреждение, что прогон проверочный. |
| `--nicks` | Вместо имён — ники со ссылкой на профиль (карта: `config/nicks.php`, заполняется вручную — в экспорте username нет). В HTML — кликабельные ссылки, в canvas-графиках — ники без ссылок. |
| `--debug` | Таблица таймингов обработчиков (Stopwatch) + Twig без авто-перезагрузки. |

### Примеры

```bash
# Простой запуск
php bin/chatstats generate ~/Downloads/ChatExport_2026-09-01

# Своё имя файла и заголовок страницы
php bin/chatstats generate ~/Downloads/ChatExport_2026-09-01 --key=family --title="Семейный чат"

# Быстрая проверка после изменений кода: только первые 2000 сообщений
php bin/chatstats generate ~/Downloads/ChatExport_2026-09-01 --key=check --limit=2000

# Ники со ссылками вместо имён
php bin/chatstats generate ~/Downloads/ChatExport_2026-09-01 --nicks
```

## Как это работает / производительность

- Парсер потоково читает сообщения из файлов экспорта (генератор) и кэширует их нативным
  `serialize` чанками по 5000 в `var/cache/parsers/<signature>-v3/`.
- Вся статистика считается **за один проход** по сообщениям
  (ленивый однопроходный агрегатор `MessageCollection`).
- Результат всех обработчиков кэшируется в `var/cache/results/<sig>.ser`: повторные прогоны
  вообще не читают сообщения (~40 МБ даже на чатах с миллионом сообщений).
- Кэши инвалидируются автоматически: кэш сообщений — при изменении экспорта (имена файлов + mtime),
  кэш результатов — при изменении кода/конфигов (mtime `src/` и `config/`).
- Прогоны с `--limit` используют отдельный кэш и никогда не трогают полный.

## Конфигурация

- `config/users.php` — карта «ник → настоящее имя», применяется при парсинге.
- `config/nicks.php` — карта «имя в чате → ник в Telegram (без @)» для `--nicks`.
- `config/words.php` — стоп-слова и алиасы для анализа слов.
