# Установка и использование chatStats

## Требования

- **PHP >= 8.4** (синтаксис PHP 8 используется свободно).
- Расширение **ext-mbstring**.
- Composer.

## Установка

```
composer install
```

`vendor/`, `var/` и `public/data` находятся в `.gitignore` — это рабочие артефакты, а не часть репозитория.

## Запуск через Docker (без установки PHP на хост)

Если на хосте нет PHP, но есть Docker:

```bash
# Сборка образа (один раз)
docker build -t chatstats .

# Генерация: папка экспорта монтируется read-only, результат — в ./var/html
docker run --rm \
  -v /путь/к/экспорту:/export:ro \
  -v $(pwd)/var:/app/var \
  chatstats generate /export --key=my-chat
```

Особенности:

- Внутри контейнера код лежит в `/app`, точка входа — `php /app/bin/chatstats`.
- Обязателен один монт: папка экспорта (read-only в `/export`) — как аргумент команды.
- **Монт `./var`** сохраняет на хосте и HTML-результат, и кэши (сообщений и результатов):
  повторные прогоны внутри контейнера будут такими же быстрыми, как на хосте.
  Без этого монта результат остаётся внутри контейнера и пропадёт после `--rm`.
- Все опции CLI работают как обычно (см. ниже): `--limit=2000` для быстрых проверок,
  `--nicks`, `--no-cache`, `--debug` и т.д.
- `docker run --rm chatstats list` — список команд; `--help` — справка по опциям.
- Образ собирается с PHP 8.4 CLI (совпадает с требованием `composer.json`), зависимости
  ставятся при сборке — на хосте ничего устанавливать не нужно.

## Команда generate

```
php bin/chatstats generate <папка-экспорта> [--key=<ключ>] [--title=<заголовок>]
                                        [--no-cache] [--rebuild] [--limit=<N>] [--nicks] [--debug]
```

### Аргументы и опции

| Параметр | Описание |
|---|---|
| `<папка-экспорта>` | Обязательный аргумент — папка с HTML-экспортом чата Telegram Desktop. Несуществующая папка → ошибка и **exit 1**. |
| `--key=<ключ>` | Имя выходного файла: `var/html/<key>.html`. По умолчанию — имя папки экспорта. |
| `--title=<заголовок>` | Заголовок страницы. По умолчанию — ключ. |
| `--no-cache` | Не читать и не писать кэш сообщений. |
| `--rebuild` | Пересобрать кэш сообщений принудительно. |
| `--limit=<N>` | Обработать только первые **N** сообщений — для быстрых проверок на больших чатах (секунды вместо минут). Кэш при лимите отдельный (сигнатура с суффиксом `-limit-N`), полный кэш не затирается. В выводе — предупреждение, что прогон проверочный. Рекомендуется для регресс-проверок после изменений кода. |
| `--nicks` | Вместо имён пользователей выводить их ники со ссылкой на профиль (`https://t.me/<ник>`). Ники берутся из карты `config/nicks.php` («имя → ник», заполняется вручную — в экспорте username нет). В HTML-частях — кликабельные ссылки, в canvas-графиках — ники без ссылок (Chart.js не поддерживает ссылки). Без флага поведение не меняется. |
| `--debug` | Таблица таймингов обработчиков (Stopwatch) и Twig без авто-перезагрузки. |

### Выход

- Единственный артефакт — статическая страница `var/html/<key>.html`.
- При успехе в консоль выводится путь к файлу и число панелей: `Готово: var/html/<key>.html (27 панелей)`.
- Наверху страницы — сводка KPI (сообщения, участники, дни, медиа, реакции, знаки) и «забавные факты»; ниже — аккордеонами 27 панелей статистики. Тема (светлая/тёмная) переключается кнопкой в правом верхнем углу и запоминается в браузере.

### Про кэш

При первом запуске сообщения парсятся потоково и пишутся чанками (по 5000) в `var/cache/parsers/<signature>-v3/00000.ser...` (суффикс `-v3` — версия формата: меняется при обновлении версии инструмента, старый кэш без новых полей данных не используется). Кэш автоматически пересобирается при любом изменении папки экспорта (сигнатура = имена файлов + mtime). Результат обработчиков кэшируется в `var/cache/results/<sig>.ser` — повторные прогоны не читают сообщения и не пересчитывают статистику (память ~20-40MB даже на чатах с миллионом сообщений); кэш результатов инвалидируется при изменении кода или конфигов. Подробнее — в [Архитектуре](architecture.md#память-и-кэши).

> **Память**: сообщения не хранятся в памяти целиком — читается по одному чанку, поэтому пик памяти не зависит от размера чата (полный прогон 1.1M сообщений — ~350MB; повторные — ~20-40MB).

## Примеры

```bash
# Простой запуск по папке экспорта
php bin/chatstats generate ~/Downloads/ChatExport_2026-09-01

# Своё имя файла и заголовок страницы
php bin/chatstats generate ~/Downloads/ChatExport_2026-09-01 --key=family --title="Семейный чат"

# Полный пересбор без кэша, с таймингами
php bin/chatstats generate ~/Downloads/ChatExport_2026-09-01 --no-cache --debug

# Быстрая проверка после изменений кода: только первые 2000 сообщений
php bin/chatstats generate ~/Downloads/ChatExport_2026-09-01 --key=check --limit=2000

# Ники со ссылками на профили вместо имён (карта: config/nicks.php)
php bin/chatstats generate ~/Downloads/ChatExport_2026-09-01 --nicks
```

## Проверка после изменений

Тестов в проекте нет; проверка = запустить генерацию и визуально сверить сгенерированный HTML (панели, значения, отсутствие ошибок).
